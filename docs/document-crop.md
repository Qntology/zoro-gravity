# 문서 크롭: SigLIP2 로 읽을 곳 고르기

명세의 Stage 1(여백 · 고정 안내문을 버리고 수기 입력란 · 서명란 · 증빙 표만 자르기)을 구현한 문서입니다.
명세의 `indra-ocr` 은 라이선스 문제로 쓰지 않고, logis-center 의 SigLIP2 방식을 따랐습니다. 코드는 직접 구현했습니다 (`core/src/ai/siglip2`).

## 1. 모델

| 항목 | 값 |
| --- | --- |
| 모델 | `google/siglip2-so400m-patch16-naflex` (**Apache-2.0**) |
| 위치 | 모델 폴더의 `siglip2` (`%LOCALAPPDATA%\zorogravity\models\siglip2` 등) |
| 변환 | `zorogravity-gguf auto %LOCALAPPDATA%\zorogravity\models\siglip2` → `siglip2-q8.gguf` 0.88 GB + `mmproj-siglip2-bf16.gguf` 0.86 GB (비전 BF16, 텍스트 Q8_0). 텍스트 층 출력 상대오차 평균 0.54% |
| 단계 | 페이지를 읽을 때는 **비전 타워만** (ROCm 816 MB), 문구를 인코딩할 때는 텍스트 타워만. 실행 중에는 텍스트 타워가 올라오지 않습니다 |
| 격자 | 패치 16 px, 페이지당 최대 256 패치. A4 는 19×13 격자라서 **칸 하나가 글자 여러 줄을 덮습니다** |

## 2. 흐름

```
페이지 → 기울기 보정 → 잉크 분석으로 조각 나누기 ─┐
       └→ SigLIP2 비전 → 패치 특징 → 시각 앵커 점수 ┴→ 조각마다 읽을지 · 무엇인지 판정 → gocr
```

1. **기울기 보정** (`ink::estimate_skew`, `deskew`): 글자 행이 곧을 때 행 프로파일의 변동이 가장 큽니다. 기운 채로는 행 사이 여백이 사라집니다.
2. **조각 나누기** (`layout`): 여백을 따라 자르고(XY-cut), 큰 덩어리는 글자 행 사이에서 나눕니다. 잉크가 있으면 어떤 조각에든 들어갑니다. 패치 격자로 자르지 않는 이유는 칸 하나가 94 px 라서 글자가 잘리기 때문입니다.
3. **패치 경쟁** (`arena`): 칸마다 종류끼리 겨뤄 주인을 정합니다. 두 종류 이상이 다투는 칸의 차이 중앙값 × 0.5 가 확정 기준이고, 확정 칸이 없는 종류는 탈락한 뒤 남은 종류끼리 다시 겨룹니다 (최대 4라운드). logis-center 의 `nms_arena` 와 같은 방식이고 코드는 직접 구현했습니다.
4. **판정** (`plan`): 조각이 덮는 칸의 주인을 세어 안내문과 표 · 입력란을 가릅니다. 제목은 평균 점수로 고릅니다 (영토로 고르면 192장에서 2장 나빠졌습니다).
5. **크롭 NMS**: 넓이의 80% 이상이 더 큰 크롭 안에 있는 크롭을 뺍니다. 강제로 겹쳐 자른 조각이 같은 글을 두 번 읽지 않습니다. 제목과 서명은 빼지 않습니다.
6. **크롭 다듬기**: 괘선을 뺀 글자 경계로 줄이고(`text_box`), 글자 높이에 맞춰 키웁니다. gocr 시간은 패치 수에 비례합니다.

### 무엇을 버리는가

값을 놓치면 판단이 틀어지지만 안내문을 더 읽는 것은 시간만 더 듭니다. 그래서 **신호 세 개가 모두 맞을 때만** 버립니다.

- 괘선 없이 고른 줄이 이어진 문단 모양이고 (`layout::runs`)
- 글자가 고정 안내문처럼 작고 (자필 진정서는 여기서 걸러집니다)
- 조각의 잉크 칸 절반 이상이 안내문의 확정 영토여야 합니다. 칸마다 다음 종류보다 0.05 이상 앞서야 영토로 칩니다

서명 · 날인은 다른 조각과 겹쳐도 따로 냅니다 (서명 검증과 합성 위치에 씁니다). 시각 앵커 파일이 없으면 버리는 조각 없이 잉크 조각을 모두 읽습니다.

## 3. 문구 앵커 대신 시각 앵커를 쓰는 이유

logis-center 는 필드 이름 같은 문구를 텍스트 타워로 인코딩해 패치와 코사인을 잽니다. 같은 방식을 한국어 서식에 재 보았습니다.

합성 서식 32장, 패치 256, 3×3 평균한 칸 단위 AUC 입니다 (0.5 는 구분 못 함).

| 영역 | 문구 앵커 최고 | 시각 앵커 (처음 보는 서식 종류) |
| --- | --- | --- |
| 서명 · 날인 | 0.904 `a red stamp seal` | **0.994** |
| 표 | 0.808 `table of numbers` | **0.906** |
| 안내문 | 0.766 `fine print paragraph` | **0.916** |
| 제목 | 0.577 | **0.965** |
| 입력란의 값 | **0.566** | **0.937** |

- 문구는 도장 · 표 · 잔글씨 같은 **모양**은 찾지만, 한국어 라벨과 값은 찾지 못합니다.
- 패치를 576 · 1024 로 늘려도 값은 나아지지 않았습니다 (0.50, 0.47). 해상도 문제가 아닙니다.
- 문서 종류도 맞히지 못합니다. 16종에서 문구 분류 정확도는 최고 25% 입니다. 그래서 **문서 분류는 SigLIP2 로 하지 않고** 명세대로 제목 조각을 읽어 Zoro 가 판단합니다.
- 패치 특징 자체에는 정보가 있습니다. 서식 종류를 통째로 뺀 선형 분류기가 위 표의 오른쪽 값을 냅니다.

그래서 문구 벡터 자리에 **정답 서식으로 학습한 선형 가중치**를 넣었습니다 (`probe.rs`, `models/siglip2/crop_probe.bin`). 패치당 내적 다섯 번이라 실행 비용이 없습니다.

**한계**: 앵커는 합성 서식으로만 학습했습니다. 실제 스캔으로 다시 학습하기 전에는 실제 서식에서의 성능을 모릅니다.

## 4. 측정

합성 서식 16종. 정답 상자 안 잉크의 90% 이상이 크롭에 들어가면 찾은 것으로 칩니다 (표는 테두리가 잘리므로 80%).
시각 앵커는 **그 서식 종류를 빼고 학습한 것**으로 평가했습니다 (`crop_eval` 네 번째 인자).

| 192장 (서식 16종) | 값 | 서명 | 표 | 제목 | 제목 표시 | 서명 크롭 | 안내문 남음 | 면적 | 페이지당 패치 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 잉크 분석만 (앵커 없음) | 100% | 100% | 99% | 100% | 없음 | 없음 | 99% | 0.29 | 8,167 |
| 잉크 분석 + 시각 앵커 (평균 점수) | 100% | 100% | 99% | 100% | 190/192 | 168/168 (헛것 1) | 67% | 0.27 | 7,478 |
| **잉크 분석 + 시각 앵커 + 패치 경쟁** | **100%** | **100%** | **99%** | **100%** | **190/192** | **168/168** (헛것 1) | **54%** | **0.27** | **7,237** |

면적은 페이지 대비 크롭 넓이의 합입니다. 시험 세트 64장도 같습니다 (값 · 서명 · 제목 100%, 표 100%, 서명 크롭 56/56, 면적 0.27, 안내문 56%, 패치 7,087).

버리는 영토 비율은 0.3 ~ 0.5 에서 결과가 같고 0.6 부터 안내문이 더 남습니다. 칸 하한 0.05 는 페이지 전체가 근소하게 겨룰 때 값을 버리지 않도록 넣었습니다. 하한을 0.15 로 올리면 이득이 사라집니다 (안내문 68%).

- 값 누락으로 잡힌 1건(`poa_10`)은 기울기 때문에 정답 상자가 부풀어 생긴 오탐이고, 글자는 크롭 안에 있습니다.
- 면적 절감의 대부분은 **잉크 분석**에서 나옵니다. SigLIP2 가 더하는 것은 안내문 제거보다 **이름표**입니다: 제목(Gate 0), 서명 위치(Gate 1), 표(프롬프트).
- 안내문이 절반쯤 남는 것은 한두 줄짜리가 많아서입니다. 문단 모양이 아니면 버리지 않습니다.
- 패치 경쟁은 칸 수백 개를 비교할 뿐이라 페이지당 1 ms 도 안 걸립니다. 그래서 병렬로 돌리지 않습니다.

### 읽기 (RX 6600)

시험 세트 64장, ROCm, 기본 설정입니다.

| 항목 | 결과 |
| --- | --- |
| 값을 글자 그대로 읽음 | **378/440 (85.9%)**, 진정서를 빼면 341/372 (91.7%) |
| 제목을 그대로 읽음 | 60/64 |
| 페이지당 시간 | **8.7 s** (8장씩 묶어 읽을 때) |

**묶음과 병렬의 효과** (`read_eval`). 모두 값 378/440 이고 틀린 항목까지 같습니다.

| 설정 | 장당 | 비전 | 프리필 | 디코딩 | 적재 등 | 토큰 |
| --- | --- | --- | --- | --- | --- | --- |
| 한 장씩 읽기 | 13.63 s | 3.64 | 1.31 | 5.73 | 2.95 | 527 |
| 8장씩 묶어 읽기 (`read_pages`) | 11.09 s | 3.63 | 1.28 | 5.69 | 0.48 | 527 |
| + 같은 격자 비전 묶음 | 10.96 s | 3.51 | 1.28 | 5.69 | 0.48 | 527 |
| + 패치 경쟁 | 10.59 s | 3.42 | 1.26 | 5.44 | 0.48 | 510 |
| + 매핑 로더 · 비전 파일 분리 | 10.75 s | 3.46 | 1.31 | 5.65 | 0.33 | 510 |
| + Q8_0 다중 행 커널 · 버퍼 캐시 · 직접 업로드 | **8.70 s** | 3.32 | 0.94 | 4.17 | 0.27 | 510 |
| 위와 같고 한 장씩 읽기 | 9.82 s | 3.39 | 0.96 | 4.22 | 1.24 | 510 |

- **가장 큰 이득은 모델을 장마다 오가지 않는 것**입니다 (2.5 s 감소). 민원 한 건의 서류는 `read_pages` 로 함께 읽어야 합니다.
- 명세의 Dynamic Batching 은 넣었지만 효과는 3% 입니다. 주의 계산량은 이미지마다 패치 수의 제곱에 비례해서, 묶어도 계산 자체는 줄지 않고 호출 비용만 줄어듭니다. 한 장 안에서는 묶음당 1.4 조각이고, 64장 전체로는 3.4 조각입니다.
- 픽셀 계산(기울기 · 곧게 펴기 · 잉크 지도 · 계획 · 크롭 자르기)은 장당 150 ms 이고 이제 페이지 · 크롭 단위로 병렬입니다 (`rayon`). 코어가 많아도 줄일 수 있는 시간이 여기까지입니다.
- 언어 디코딩은 조각을 하나씩 읽습니다. 가장 큰 단계이지만 조각마다 쓰는 길이가 달라서 묶으려면 디코더에 묶음 마스크가 필요합니다.

| 단계 | 병렬 / 묶음 |
| --- | --- |
| 페이지 픽셀 계산 · 크롭 자르기 | CPU 병렬 |
| SigLIP2 비전 | 격자가 같은 페이지를 8장씩 묶음 |
| gocr 비전 | 격자가 같은 조각을 4,096 패치까지 묶음 |
| 패치 경쟁 · 크롭 NMS | 순차 (1 ms 미만) |
| gocr 언어 | 조각 하나씩 |

설정별 비교입니다 (서식 16종 1장씩, 입력란은 표 프롬프트). 입력란을 일반 프롬프트로 읽으면 같은 시간에 78.2% 입니다.

| 조각 패치 상한 | 그대로 읽음 | 페이지당 |

입력란은 표 프롬프트로 읽습니다. `<td>상호:</td><td>...</td>` 처럼 항목과 값이 칸으로 묶여 나오고, 틀린 글자에는 낮은 확신도가 붙습니다 (`min_confidence`).

- **ROCm 을 쓰세요.** Vulkan 은 일반 가중치가 시스템 메모리에 있어서 같은 페이지가 6배 느립니다 (OCR 120 s, 비전 조각당 최대 17 s).
- 명세의 문서당 185 ms 는 이 GPU 에서 나오지 않습니다.
- 합성 글자로 잰 값입니다. 진정서의 손글씨는 궁서체를 흔들어 찍은 흉내라서 실제 악필 성능은 모릅니다.

## 5. 다시 만들기

```bat
:: 합성 서식 (실제 개인정보 없음, out/ 은 저장소에 올라가지 않습니다)
python scripts\gen_sample_forms.py out\forms 12 7
python scripts\gen_sample_forms.py out\forms_test 4 1234

:: 패치 특징 뽑기
target-rocm\release\examples\siglip2_dump.exe grids out\forms 256 out\feat
target-rocm\release\examples\siglip2_dump.exe grids out\forms_test 256 out\feat_test

:: 시각 앵커 학습 · 평가 (GPU 불필요)
python scripts\train_crop_probe.py out\feat out\forms %LOCALAPPDATA%\zorogravity\models\siglip2\crop_probe.bin out\feat_test out\forms_test out\loo
target\release\examples\crop_eval.exe out\forms out\feat %LOCALAPPDATA%\zorogravity\models\siglip2\crop_probe.bin out\loo

:: 계획을 그림으로 보기 · 페이지 끝까지 읽기
target\release\examples\crop_view.exe 이미지.jpg 특징.bin %LOCALAPPDATA%\zorogravity\models\siglip2\crop_probe.bin 출력.png
target-rocm\release\examples\read_page.exe 이미지.jpg 정답.json
```

## 6. 아직 없는 것

- 실제 스캔으로 학습한 앵커와 그 평가
- gocr 언어 디코딩의 묶음 처리
- 인쇄 · 수기 구분 (`is_printed`)

읽은 글을 항목별 사실로 바꾸는 단계는 `core/src/extract.rs` 입니다. 결과는 [stabilization-report.md](stabilization-report.md) 3.2 에 있습니다.

# 키오스크 양식 입력 전환 기획 (민원 파트별)

민원인이 서류를 미리 준비하지 않고, 키오스크에서 민원 종류를 고른 뒤 양식에 직접 입력하는 흐름으로 바꾸는 기획입니다.
P1(고충민원 양식 접수, 9절)과 P2~P6(복지 · 정산 · 허가 · 증명, 공무원 접수 목록, 10절)을 구현했습니다. 그 뒤 서류 스캔과 합성 대장을 넣어 흐름을 다시 줄였습니다 (11절).

> 상태: 1~10절은 양식 입력 전환 당시의 기록입니다. **지금 흐름은 11절과 [stabilization-report.md](stabilization-report.md) 입니다.** "양식 건은 모두 공무원이 확정한다"는 2절의 원칙은 합성 대장과 신분증 스캔이 들어오면서 바뀌었습니다. 명세는 업로드된 `zeze.txt` 를 기준으로 합니다. 이 명세의 `GovGraph-ZEZE` 와 `ZEZE` 는 이전 이름이고, 프로젝트 이름은 zorogravity 입니다. 명세의 서류 목록과 흐름 중 코드와 다른 부분은 **확인** 으로 표시했습니다.

## 1. 현재 상태 (코드 확인 결과)

| 영역 | 현재 | 파일 |
| --- | --- | --- |
| 민원인 화면 | 단계 이름과 문구만 있는 틀. 입력 · 버튼 · 문서 투입 동작이 없음 | `app/src/KioskView.tsx` |
| 문서 투입 | "서류를 스캐너에 넣어 주세요" 문구만 있음. 스캐너 연결 코드 없음 | `app/src/KioskView.tsx` |
| 준비 상태 | 모델 세 개가 모두 있어야 문구가 바뀜. 지금은 "창구를 준비하고 있습니다" | `app/src-tauri/src/lib.rs` `engine_ready` |
| 민원 모델 | `CaseFile` 한 건에 신청 정보 · 서류 · 서명 · 소명이 모임 | `core/src/case.rs` |
| 민원 종류 | 5대 법정 민원 (복지·지원금·허가·증명·고충). 분류는 접수 양식이 정함 | `core/src/case.rs`, `gate0_router.rs` |
| 필수 서류 | 종류별 목록. 서류 이름이 스캔 결과와 맞아야 함 | `gate0_router.rs` `mandatory_docs` |
| 서류 누락 | Gate 1 `Hold` → 보완요구(7일) 또는 재투입. 누락 상태로 Gate 2 진입 불가 | `gate1_formal.rs`, `pipeline.rs` |
| 진실 우선순위 | 이체내역 > 인쇄된 계약서 > 신청서 손글씨. 인쇄본이 있어야 정정 · 잠금이 가능 | `gate2_consistency.rs` |
| 자동 확정 | 기본은 보조 모드. 규칙 검사가 하나라도 미확인이면 자동 확정 안 함 | `docs/automation-mode.md` |
| 저장 | 메모리에만 있음 (영속 저장 미구현) | `core/src/store.rs` |

**핵심 문제**: 지금 규칙은 "서류가 있어야 통과한다"를 전제로 합니다. 민원인이 서류를 준비하지 못하면 모든 건이 Gate 1 에서 누락으로 걸립니다. 그래서 양식 입력으로 바꾸려면 **서류를 누락으로 보지 않는 새 상태**가 필요합니다 (4절 공통 설계).

## 2. 전환 원칙

1. **민원인은 서류를 준비하지 않습니다.** 키오스크는 입력, 서명, 접수 번호 발급까지만 합니다.
2. **신고값과 증빙값을 구분합니다.** 민원인이 입력한 값은 신고값입니다. 인쇄된 원본을 공무원이 확인해야 증빙값이 됩니다. 신고값만으로는 정정 · 잠금 · 자동 판정을 하지 않습니다.
3. **증빙 확인은 창구에서 합니다.** 공무원이 원본을 확인하고 필요하면 스캔합니다. 스캔 장비는 공무원 쪽에 둡니다.
4. **양식으로 접수된 건은 모두 공무원이 확정합니다.** 자동화 모드 대상이 아닙니다. 증빙이 없어 규칙 검사가 미확인으로 남으므로, 기존 불변식(5번)으로도 자동 확정이 막힙니다.
5. **민원인 화면에는 내부 정보를 보내지 않습니다.** 기존 원칙을 그대로 둡니다. 공무원 명령은 공무원 창에서만 받습니다.

## 3. 결정 사항 (먼저 정해야 함)

| 번호 | 질문 | 권장 | 이유 |
| --- | --- | --- | --- |
| D1 | 증빙 확인은 누가, 언제 하는가 | 접수 후 창구에서 공무원이 원본 확인 · 스캔 | 민원인이 서류를 준비하지 않아도 됨 |
| D2 | 신고값과 인쇄본이 다르면 | 정정하지 않고 "확인 필요"로 표시 | 신고값만으로 정정하면 민원인 입력이 판정을 바꾸게 됨 |
| D3 | 양식 접수 건의 자동 확정 | 금지 (보조 모드 고정) | 증빙 전 자동 확정은 근거가 없음 |
| D4 | 본인 확인 방식 | 1차: 이름 · 생년월일 입력 + 창구 신분증 확인. 주민번호 전체 입력은 마스킹 | 주민번호 원문 입력은 민감정보. 본인인증 연동은 외부 협의 필요 |
| D5 | 민원 종류 선택 주체 | 민원인이 선택 (쉬운 이름과 예시 제공) | 현재는 접수 양식 코드가 정함. 잘못 고르면 흐름이 틀어짐 |
| D6 | 모델 의견 (Gate 0) | 양식 경로에서는 스캔 서류가 없으므로 끔 | 현재 모델 입력은 스캔된 서류 종류뿐 |
| D7 | 접수 저장 위치 | 접수 번호 발급 후 공무원 콘솔 목록으로 전달. 저장소는 별도 결정 | 영속 저장이 아직 없음 |

## 4. 공통 흐름과 공통 설계

### 4.1 민원인 화면 (키오스크)

```
[1] 민원 선택 (5종, 쉬운 이름 + 예시)
  → [2] 본인 확인 (이름 · 생년월일 앞 6자리 · D4)
  → [3] 민원별 입력 (3~6 화면, 숫자 키패드 · 한글 키보드)
  → [4] 입력 내용 확인 (수정 가능)
  → [5] 서명 (해당 민원만. 서명 기준 실패 시 다시 받음)
  → [6] 접수 완료 (접수 번호 · "창구에서 확인할 서류" 안내 출력)
```

현재 `STEPS` 는 "서류 및 서명 확인 / 내용 대조 / 완료"입니다. 이 단계 이름은 위 흐름에 맞게 바뀝니다.

### 4.2 공통 상태 설계 (core)

| 항목 | 내용 |
| --- | --- |
| 입력 출처 | `CaseSource` 추가: 키오스크 양식 · 스캐너 · 공무원 입력. 양식 접수는 신고값으로 들어옴 |
| 신고값 / 증빙값 | 현재 `LeaseFacts`, `BankFacts` 등은 값 하나로 들어감. 출처 표시를 붙이거나 신고 전용 구조를 둠 |
| 서류 제출 방식 | 서류마다 `kiosk_form`(민원인 입력으로 갈음) · `counter_check`(창구 확인 대기) · `scanned`(스캔 완료) 중 하나 |
| Gate 1 누락 처리 | `counter_check` 는 누락이 아니라 **창구 확인 대기**로 셈. 보완요구 대상이 아님 |
| Gate 2 신고값 처리 | 인쇄본이 없는 비교는 **확인 필요**. 정정 · 잠금 · 강제 차단을 하지 않음 |
| Gate 0 모델 의견 | 양식 경로에서는 입력 텍스트 기준 의견만 두거나 끔 (D6) |
| 확정 | 양식 접수 건은 항상 공무원 확정 (D3) |

### 4.3 키오스크 ↔ 공무원 콘솔

- 현재 키오스크는 준비 여부만 받습니다. 접수 데이터를 공무원 창으로 보내는 명령이 없습니다.
- 추가할 명령: `submit_form` (키오스크 → 코어). 응답은 접수 번호만 돌려줌. 공무원 창에는 `officer` 라벨로만 이벤트를 보냄.
- 개인정보: 주민번호 원문은 `Person::identifier` 에만 두고, 로그와 화면 표시는 마스킹. 접수 후 키오스크 메모리에서 지움.

## 5. 민원 파트별 기획

각 파트마다 **입력 항목**, **서류 제출 방식**, **현재 규칙 연결**, **코드 변경**, **확인 질문**을 적었습니다.

### 5.1 고충민원 (Grievance) — 서류 없음, 가장 단순

| 항목 | 내용 |
| --- | --- |
| 코드 | `Category::Grievance`. 필수 서류 없음 (`mandatory_docs` 빈 목록) |
| 민원인 입력 | 내용 (자유 입력, 한글 키보드), 연락처, 처리 희망 (선택), 제목 (선택) |
| 서류 | 없음. 증빙이 있으면 창구에서 제출 가능 |
| 서명 | 없음 (현재 코드상 필요 민원이 아님) |
| 현재 규칙 | `pipeline.rs` 에서 고충민원은 Gate 1~3 을 건너뛰고 요약 초안 후 보류 (`hold_with_draft`) |
| 모델 | 요약 3줄 초안과 부서 후보. 숫자는 원문과 대조 (`drafting.rs`). 부서는 정해진 목록 안에서만 |
| 코드 변경 | 입력 화면 (본문 자유 입력), `grievance_text` 를 `submit_form` 으로 받기. 규칙 변경 없음 |
| 확인 질문 | 본문 최대 길이, 익명 접수 허용 여부, 연락처 필수 여부 |

**왜 먼저**: 서류 흐름이 없어서 키오스크 화면 · 명령 · 접수 번호 흐름을 먼저 검증할 수 있습니다.

### 5.2 복지 (Welfare) — 월세 지원 계열, 규칙이 가장 많음

| 항목 | 내용 |
| --- | --- |
| 코드 | `Category::Welfare`. 필수 서류: 신청서, 임대차계약서, 이체내역서, 금융정보동의서 |
| 민원인 입력 | 신청 월세, 계약서에 적힌 월세, 최근 이체액, 신청 계좌, 통장 계좌, 임대인 정보 (확인), 소명 선택 |
| 소명 선택 | 신청서 오타 / 현금 직접 지급 / 수리비 공제 (영수증 있음·없음) / 자유 서술 (`Excuse`) |
| 동의 | 금융정보 조회 동의: 화면 동의 + 서명 (D1 과 함께 확인) |
| 서명 | 필요 (`requires_signature`). 기준은 획수 2회 이상, 서명란 15% 이상, 한 줄 직선 아님 |
| 창구 확인 | 임대차계약서 원본, 이체내역서, 통장 사본, 금융정보동의서 (서명본 확인) |
| 현재 규칙 연결 | Gate 2 `check_rent` (신청 · 계약 · 이체 금액), `lock_account` (신청 계좌 · 통장 계좌) |
| 신고값 처리 (D2) | 금액 차이 → "확인 필요 (창구에서 계약서 · 이체내역 확인)". 계약서 금액으로 정정하지 않음. 계좌는 잠그지 않고 "불일치, 확인 필요" |
| 소명 처리 | 소명 선택은 그대로 받음. 소명이 있으면 "증빙 확인 후 판단"으로 표시 |
| 코드 변경 | `CaseSource` · 서류 제출 방식 추가. `check_rent` · `lock_account` 에 신고값 경로 추가 (확정 대신 확인 필요). 기존 테스트(명세 Case 2-B 등) 는 인쇄본 경로로 유지 |
| 확인 질문 | 월세 지원의 근거 법령 (명세 확인), 금융정보동의를 키오스크 서명으로 갈음해도 되는지, 임대인 정보가 필요한지 |

**왜 두 번째**: 규칙이 가장 많아서, 신고값 · 증빙값 분리가 맞게 되었는지 확인하기 좋습니다.

### 5.3 지원금 정산 (Subsidy) — 사용 내역 표 중심

| 항목 | 내용 |
| --- | --- |
| 코드 | `Category::Subsidy`. 필수 서류: 정산총괄표, 영수증철, 세금계산서, 통장사본 |
| 민원인 입력 | 지원 사업명 (목록 또는 입력, 목록 내용 확인 필요), 사용 항목 표 (항목 · 금액 · 증빙 있음/없음, 행 추가 · 삭제), 합계 (자동 계산), 세금계산서 발행 여부 · 건수, 수령 계좌 |
| 서명 | 현재 코드상 필요 민원이 아님. 정산 신청서 서명 여부 확인 필요 |
| 서류 | 정산총괄표는 키오스크 표로 만들어 출력 (공식 양식인지 확인). 영수증철 · 세금계산서 · 통장 사본은 창구 확인 |
| 현재 규칙 연결 | 정산 전용 규칙 없음. `check_manual_amount` (증빙 합계 · 요청 금액) 는 있지만 파이프라인에서 호출되지 않음 (테스트만 사용) |
| 신고값 처리 | 신고 합계는 "확인 필요". 증빙 합계가 신고보다 크면 차이만큼 증빙이 있어야 한다는 기존 규칙 (`check_manual_amount`) 을 창구 확인 단계에서 적용 |
| 코드 변경 | 정산 표 입력 화면, 합계 계산, 정산총괄표 출력. `check_manual_amount` 를 파이프라인에 연결 |
| 확인 질문 | 증빙 없는 항목의 인정 범위, 정산총괄표 공식 양식 여부, 사업별 정산 규칙 |

### 5.4 허가 · 신고 (Permit) — 영업 · 시설 신고 계열

| 항목 | 내용 |
| --- | --- |
| 코드 | `Category::Permit`. 필수 서류: 영업신고서, 위생교육필증, 소방안전필증, 건축물대장 |
| 민원인 입력 | 신고인 정보, 상호 · 업종 · 영업장 주소 · 면적, 위생교육 이수 여부와 필증 번호 · 일자, 소방안전 필증 번호 · 일자, 건축물 용도 (선택) |
| 서명 | 현재 코드상 필요 민원이 아님. 영업신고서 서명 여부 확인 필요 |
| 창구 확인 | 위생교육필증 원본, 소방안전필증 원본, 건축물대장 (열람 · 발급본) |
| 현재 규칙 연결 | 정산처럼 전용 규칙 없음. 필수 서류 누락 검사만 있음 |
| 코드 변경 | 입력 화면, 서류 제출 방식 (창구 확인). 규칙 변경은 확인 후 결정 |
| 확인 질문 | 업종별 필수 항목 목록 (명세 Part 2 §1.1 확인), 건축물대장을 열람 조회로 갈음해도 되는지 |

### 5.5 증명 · 대리 (Cert) — 인감 대리발급 계열, 가장 어려움

| 항목 | 내용 |
| --- | --- |
| 코드 | `Category::Cert`. 필수 서류: 위임장, 위임자 신분증 사본, 대리인 신분증 |
| 민원인 입력 | 위임자 정보 (이름 · 생년월일 · 주민번호 마스킹), 대리인 정보 (이름 · 생년월일 · 관계), 발급 종류 · 용도, 위임장 작성일 |
| 서명 | 필요 (`requires_signature`). 위임자 · 대리인 중 누구의 서명인지 확인 필요 |
| 위임장 유효기간 | 작성일로부터 180일 (`POA_MAX_DAYS`). 기간이 지나면 Gate 1 `Reject` 후보가 됨. 키오스크는 입력 단계에서 미리 경고 |
| 창구 확인 | 위임장 원본 (또는 키오스크 출력본과 서명 확인), 위임자 신분증 사본 (대조), 대리인 신분증 (대면 확인) |
| 현재 규칙 연결 | Gate 1 위임장 기간 검사, 서명 검사, 서류 검사 |
| 신고값 처리 | 신고된 작성일 · 정보는 "확인 필요". 기간 초과는 처분 후보이므로 항상 공무원 확인 (불리한 처분 불변식) |
| 코드 변경 | 위임 입력 화면, 기간 미리 경고, 창구 확인 목록 |
| 확인 질문 | **인감 날인이 법적으로 필요한지** (필요하면 이 파트는 창구 중심이 됨), 위임장을 키오스크에서 만들어 서명으로 갈음해도 되는지, 대리인 서명이 필요한지 |

### 9.5 아직 없는 것 (P1 의 한계)

1. **공무원 콘솔에 접수 목록이 없습니다.** 접수 세션은 앱 메모리의 `Engine` 에 들어가지만, 화면에는 아직 나오지 않습니다 (P6).
2. **요약 초안이 생성되지 않습니다.** 명세 Part 2 §1.2 의 3줄 요약은 `TextWriter` 가 있어야 합니다. 코어에는 `ZoroBackbone` 구현이 있지만 앱에 연결하지 않았습니다. 모델 상주 정책과 함께 정해야 합니다. 지금은 "요약과 부서 배정 후 공무원이 처리합니다"라는 사유만 남습니다.
3. **제목 · 처리 희망 입력이 없습니다** (기획 5.1 에 있음).
4. **접수 세션은 저장되지 않습니다.** 앱을 끄면 사라집니다 (영속 저장 미구현).
5. **솔트는 실행할 때마다 새로 만듭니다.** 관계망 해시를 쓰는 단계 전에 고정 저장 방식을 정해야 합니다.
6. **음성 안내(명세의 캐릭터 안내)와 서명 단계는 없습니다.** 고충민원은 서명이 필요 없습니다.

### 9.6 명세와 다른 점 (확인 필요)

- 명세 Part 2 §3 의 키오스크 화면에는 "제출 서류 스캔 현황" 패널이 있습니다. 양식 접수 방식에서는 서류를 받지 않으므로 빼고 구현했습니다 (기획 2절 원칙 1).
- 명세의 단계 이름 (서류 및 서명 확인 · 내용 대조 · 완료) 은 양식 흐름에 맞춰 바꿨습니다 (민원 선택 · 정보 입력 · 내용 확인 · 접수 완료).

## 10. P2 ~ P6 구현 결과

P2(신고값 · 증빙값 구분), P3(복지), P4(지원금 정산), P5(허가 · 신고, 증명 · 대리), P6(공무원 콘솔 접수 목록) 를 구현했습니다.

### 10.1 흐름

- **민원인**: 민원 선택 → 항목 입력 (`formSchemas.ts`) → 확인 → 접수 번호. 서명이 필요한 민원은 서명 패드로 받습니다 (`SignaturePad.tsx`). 서명이 기준에 못 미치면 다시 받습니다.
- **공무원 콘솔**: 접수 목록 (확인 대기 · 이첩 완료 · 확정 완료) → 상세 → 창구 체크리스트 → 처리.
  - 고충민원: 체크리스트 후 **담당 부서로 이첩** (`transfer_intake`).
  - 그 밖의 민원: 체크리스트 후 **확정** (`confirm_form`). 원본을 확인한 서류와 신분증 확인이 모두 있어야 합니다.
  - 지원금 정산: 확인한 영수증 합계와 추가 증빙을 입력합니다. 신고 금액이 넘으면 확정이 막힙니다 (`check_manual_amount`).
- 양식 건은 창구 확인 전에는 확정할 수 없습니다. 자동 확정은 열리지 않습니다 (`gates_clear = false`).

### 10.5 E2E 중 찾아 고친 것

1. 접수 번호 날짜가 UTC 날짜로 찍힘 → 현지 날짜를 씀.
2. 양식 건의 신청인과 임대인이 빈 식별 번호 때문에 같은 사람으로 판정되어 "고위험"이 나옴 → 역할별 구분 값을 씀. 이 버그는 코어 통합 테스트가 잡았습니다.
3. 확정 목록 테스트가 이전 실행의 누적 건수에 기대고 있었음 → 상태 기준 검사로 바꿈.

### 10.6 아직 없는 것 (한계)

1. **친족 · 동일 세대 검사가 양식 건에서는 동작하지 않습니다.** 주민등록번호를 키오스크에서 받지 않아서 관계망 해시가 없습니다. 창구에서 신분증을 확인한 뒤 식별 번호 해시를 넣는 단계가 필요합니다. 지금은 체크리스트의 "신분증으로 본인 확인"에 기대고 있습니다. **이 부분은 법무 검토가 필요합니다.**
2. 허가 · 증명 입력 화면에서 위임장 기간을 미리 경고하지 않습니다. 공무원 화면의 후보 처분에만 나옵니다.
3. 공무원이 양식 건을 **반려하거나 보완 요구**하는 동작이 없습니다. 확정만 있습니다.
4. 정산총괄표 출력이 없습니다 (화면 표만 있음).
5. 요약 초안이 생성되지 않습니다 (`TextWriter` 미연결, 10.6-1 과 함께 모델 상주 정책으로 정해야 함).
6. 접수 내용과 확정 기록은 메모리에만 있습니다. 앱을 끄면 사라집니다 (영속 저장 미구현).
7. 서명 판정은 화면에서 측정한 값으로 합니다. 코어 Gate 1 이 같은 기준으로 다시 검사합니다.
8. 앱 E2E 는 화면 텍스트와 명령 결과를 확인합니다. 실제 터치 장비와 실제 서명 품질은 확인하지 않았습니다.
9. 공무원 사번은 확인 입력만 받고 인증하지 않습니다.

1, 3, 5 번은 11절에서 풀렸습니다.

## 11. 서류 스캔과 합성 대장으로 다시 줄인 흐름

정부 API 와 데이터 파이프라인이 없으므로 관계망과 공공 대장을 합성 DB 에 미리 넣어 두고 진행합니다 ([synthetic-data.md](synthetic-data.md)). 민원인이 서류를 가져오면 읽어서 채우고, 없으면 대장에서 확인합니다.

### 11.1 민원인 흐름

```
서류 넣기 → 내용 확인 → 결과
```

| 단계 | 서류가 있을 때 | 서류가 없을 때 |
| --- | --- | --- |
| 서류 넣기 | 스캔 시작. 서류 종류를 보고 민원을 정합니다 | 서류 없이 신청 → 민원 선택 |
| 내용 확인 | 읽은 값이 채워져 있습니다. 필요한 칸만 고칩니다 | 민원인이 정할 값만 적습니다 |
| 결과 | 자동 확정이면 교부 문서, 아니면 접수 번호와 대기 화면. 공무원이 끝내면 같은 화면에 결과가 나옵니다 | 같음 |

- 입력과 확인을 한 화면으로 합쳤습니다. 별도의 확인 화면이 없습니다.
- 서명은 서명이 필요한 민원에서 종이 서명이 없을 때만 받습니다.
- 소명 화면은 신분증으로 본인이 확인되고 차액이 있을 때만 나옵니다. 처음부터 묻지 않습니다.
- 서명이 두 번 약하면 창구 날인으로 넘깁니다.
- 읽은 값은 백엔드에 둡니다. 화면에는 서류 이름과 입력 칸 값만 가고, 접수할 때 백엔드가 읽은 값을 붙입니다.
- 입력 중 2분 동안 동작이 없으면 처음 화면으로 돌아갑니다. 앞 사람의 값이 화면에 남지 않게 합니다.

### 11.2 공무원 흐름

```
접수 고르기 → 사유 보기 → 남은 확인 → 처리
```

- 사번은 머리에서 한 번만 적습니다.
- 사유와 후보를 맨 위에 보입니다.
- 체크리스트는 끝나지 않은 일만 보입니다. 스캔 · 대장으로 확인된 서류는 묻지 않습니다.
- 값이 없을 때만 입력 칸이 나옵니다 (월세 · 이체액 · 계좌 · 임대인).
- 처리 버튼은 후보에 맞는 것만 보입니다. 불리한 후보는 반려 확정과 고위험 승인, 절차 후보는 보완요구, 증빙 부족은 감액 정산입니다.
- 금액을 정한 결정은 바뀐 후보를 다시 묻지 않습니다. 그 밖에 창구 값으로 후보가 바뀌면 멈추고 다시 보입니다.
- 자동화 모드는 콘솔 머리에서 켭니다. 승인자 사번과 법령 근거가 있어야 켜지고 감사 기록에 남습니다.

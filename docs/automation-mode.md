# 자동화 모드 설계 (Zoro-1)

이 문서는 공무원 심사 업무를 Zoro-1 이 자동으로 처리하는 **자동화 모드**의 설계 원칙을 적습니다.
구현은 `core/src/policy.rs`, `core/src/state_machine/pipeline.rs` 에 있습니다.

## 1. 두 가지 운영 모드

| 모드 | 기본값 | 동작 |
| --- | --- | --- |
| **보조 모드 (Assist)** | ✅ | Zoro-1 은 근거와 확률을 보여 주고, 처분은 공무원이 확정합니다. |
| **자동화 모드 (Auto)** | — | 아래 조건을 모두 만족하는 **유리한 처분**만 시스템이 자동 확정합니다. |

자동화 모드는 기본으로 꺼져 있습니다. 켜려면 다음이 **모두** 필요합니다.

- 승인자 사번 (`enable_auto` 의 `approver_id`)
- 법령 근거 조항 (`legal_basis`, 비어 있으면 거부)
- 켜고 끈 기록은 `tb_audit_log` 에 남습니다 (`AutomationChanged`)

## 2. 불변식 (코드에 설정 스위치가 없는 규칙)

1. **불리한 처분은 어떤 모드에서도 자동 확정하지 않습니다.** 반려, 위반 판정(`G3_VIOLATION_HIGH_RISK`), 위임장 효력 상실이 여기에 듭니다. `OutcomeClass::Adverse` 는 `policy.rs` 의 `disposition` 에서 항상 공무원 확인으로 넘어갑니다.
2. **절차 처분은 자동 확정하지 않습니다.** 보완요구, 진행 차단, 키오스크 재서명 요청이 여기에 듭니다.
3. **자동 확정에는 모델 확신도가 필요합니다.** 모델이 없거나, 모델이 규칙과 다른 판단을 냈으면 확신도가 `None` 이고 자동 확정은 막힙니다.
4. **모델은 증거 없이 불리한 처분을 만들 수 없습니다.** 위반 판정은 관계망에서 찾은 가까운 연결 경로가 있을 때만 규칙으로 성립합니다. 모델이 위반을 골라도 경로가 없으면 판정은 적격으로 남고, 확신도는 `None` 입니다 (`governance.rs` 의 `model_cannot_invent_an_adverse_decision_without_evidence`).
5. **규칙 검사가 하나라도 미확인이면 자동 확정하지 않습니다.** `gates_clear` 가 거짓이면 공무원에게 넘깁니다.
6. **고위험 판정은 입증 없이 정상 승인할 수 없습니다.** 승인 시도는 `G3_INTERCEPT_RUBBER_STAMP` 로 막힙니다. 허용되는 입증은 세 가지뿐입니다 (아래 4절).
7. **누락 서류를 둔 채 강제 진입할 수 없습니다.** `G1_INTERCEPT_FORCE_HOLD` 로 막히고, 7일 보완요구로 바꿀 수 있습니다.

## 3. 자동 확정 조건 (AND)

```
Auto 모드
∧ 승인 기록 있음
∧ 유리한 처분 (G3_ELIGIBLE_NORMAL 또는 G3_ELIGIBLE_HOMONYM_CLEAR)
∧ Gate 1~3 규칙 검사 모두 통과
∧ Zoro-1 확신도 ≥ 기준 (기본 0.95)
```

Gate 3 의 확신도는 유리한 판정을 기준(친족 · 세대 · 계좌)별로 따로 물은 확률의 최솟값입니다 (9절).

키오스크 접수 건에는 조건이 더 붙습니다 ([synthetic-data.md](synthetic-data.md) 7절). 필수 서류가 스캔 · 대장 · 키오스크 서명으로 모두 확인되고, 창구에서 볼 일이 없고, 신분증 스캔으로 본인이 확인되어야 합니다. 창구 확인을 거친 건은 자동 확정하지 않습니다.

확정된 건의 일정 비율(기본 10%)은 **사후 샘플 감사** 대상으로 표시합니다. 샘플은 사건 ID 의 SHA-256 으로 고르므로 같은 사건은 언제나 같은 결과가 나옵니다.

## 4. 공무원 업무별 자동화 수준

| 공무원의 업무 | 보조 모드 | 자동화 모드 | 구현 위치 |
| --- | --- | --- | --- |
| 민원 분류 | 접수 양식 코드로 확정 | 같음 (모델은 의견만) | `gate0_router` |
| 서류 누락·중복 확인 | 시스템이 표시 | 시스템이 처리, 누락은 공무원 확인 | `gate1_formal` |
| 전자서명 검증 | 키오스크가 재요청 | 같음 (처분 아님) | `gate1_formal` |
| 위임장 유효기간 | 반려 후보 → 공무원 확인 | 같음 (불리한 처분) | `gate1_formal` |
| 계좌·금액 대조 | 인쇄 원장 우선으로 고정 | 같음 | `gate2_consistency` |
| 거짓 소명 차단 | 키오스크 재선택 | 같음 | `gate2_consistency` |
| 증빙 없는 금액 수정 | 차단 | 차단 | `gate2_consistency::check_manual_amount` |
| 동명이인 판별 | 시스템이 판별 | 판별 결과가 적격이면 자동 확정 가능 | `gate3_substantive` |
| 친족 위장 임차 판정 | 공무원 확인 | 공무원 확인 (불리한 처분) | `gate3_substantive` |
| 고위험 건 승인 | 입증 필요 | 입증 필요 (항상 공무원) | `gate3_substantive::officer_approve` |
| 제3자 실명 열람 | 위험도 70% 이상만 허용 | 같음 | `gate3_substantive`, `Engine::request_unmask` |
| 보완요구 발급 | 공무원 결정 | 공무원 결정 (절차 처분) | `Engine::confirm` |
| 반려·승인 문서 작성 | 템플릿 본문 | 같음 (HWP 는 미구현) | `gate4_5_finalize` |
| 민원인 문서 누출 검사 | 항상 자동 | 같음 | `gate4_5_finalize::check_citizen_text` |
| 확정·보존·세션 삭제 | 공무원 확정 후 | 자동 확정 후 | `store::Store::finalize` |

## 5. 명세에서 다르게 구현한 부분 (검토 필요)

명세(zorogravity.txt)를 그대로 옮기지 않은 부분입니다. 근거를 함께 적습니다.

| 명세 | 구현 | 이유 |
| --- | --- | --- |
| 거짓 소명 시도에 **+8.2% 행동 페널티**를 위험도에 더함 | **구현하지 않음** | 단순 오타와 고의 거짓 소명을 구분할 수 없습니다. 행동만으로 불리한 처분을 만들 수 있게 되므로 불공정합니다. 필요하면 공무원 검토용 메모로만 추가합니다. |
| `tb_graph_entities` 를 사건 간에 누적 (다음 심사에 재활용) | **사건 범위의 관계망만** 사용 | 사건을 넘는 관계 누적은 개인정보 목적 외 이용에 해당할 수 있습니다. 법무 검토 후 도입합니다. |
| 민원 분류를 Zoro-1 이 결정 | **접수 양식 코드가 규칙**, Zoro-1 은 의견 | 분류는 증거가 있는 입력이고, 모델 오분류가 바로 처분 경로를 바꾸면 안 됩니다. |
| 위반 판정 확률을 모델이 산출 | 관계망 **증거 경로가 규칙**, 모델은 확신도 | 불리한 처분의 근거는 문서와 관계망이어야 합니다 (불변식 4). |
| `Gate 4` HWP 바이너리 생성 | **텍스트 본문** | `@rhwp/core` 연동은 아직 없습니다. |
| 모델 가중치 `jev_head.pt` | `safetensors` 로 읽음 (`JevHead::from_safetensors`) | candle 은 `.pt` 를 직접 쓰지 않습니다. 변환 후 사용합니다. |
| 모델 실행 | 텍스트 백본을 직접 구현 (`ai::zoro`), 한 번에 한 모델 · 단계별 가중치 ([weight-residency.md](weight-residency.md)) | 8 GB VRAM 에서 zoro 와 gocr 를 함께 올리지 않고, 쓰지 않는 비전 · 임베딩 표 · 출력 투영을 올리지 않기 위해서입니다. |
| `jev_head` 의 질의·선택지 위치와 점수 스케일 | **합성 · 명세 사례로 재서 고름** | 모델 폴더에서 읽을 수 없었습니다. 정답 사례 46문과 합성 62건으로 골랐고, 실제 민원으로는 검증 전입니다. [jev-head.md](jev-head.md) 6절 |
| 명세의 `Table 1~4` DB | 메모리 구현 (`store.rs`) | 영속화(SQLite 등)는 다음 단계입니다. |

## 6. 법령 검토 항목 (구현 전 법무 확인 필요)

아래는 설계 판단의 근거가 되는 법 조항입니다. **해석은 법무 검토가 필요하며, 이 문서는 법률 자문이 아닙니다.**

- **행정기본법 제20조 (자동적 처분)**: 완전 자동화된 시스템으로 처분하려면 법령상 근거가 필요하고, 재량이 개입되는 처분은 자동화하기 어렵습니다. 이 근거가 자동화 모드의 "법령 근거 조항" 입력란과 연결됩니다.
- **개인정보 보호법 제37조의2 (자동화된 결정)**: 정보주체가 자동화된 결정에 대해 설명을 요구하고, 거부할 수 있는 권리에 관한 조항입니다. 자동 확정 건의 설명 제공 방식을 정해야 합니다.
- **인공지능 발전과 신뢰 기반 조성 등에 관한 기본법 (AI 기본법)**: 공공 영역의 권리·의무 판단에 쓰이는 AI 가 고영향 인공지능에 해당하는지 확인해야 합니다. 해당하면 사람의 관리·감독과 설명 의무가 붙습니다.
- **민원 처리에 관한 법률 제22조 (보완 요구)**: 보완 요구 기한(7일)과 절차는 이 기준을 따릅니다. 구현 전에 조문과 지자체 조례를 대조합니다.
- **지방보조금 관리에 관한 법률 (보조금 정산)**: 증빙 없는 금액 인정을 막는 규칙(`check_manual_amount`)의 근거입니다.

## 7. 자동화를 켜기 전 체크리스트

- [ ] **실제 민원**의 정답으로 `jev_head` 의 위치 · 스케일 · 마스크를 다시 검증 (합성 · 명세 사례로는 끝남, [jev-head.md](jev-head.md) 6절)
- [ ] 확신도 기준(0.95)을 실제 정답 데이터로 보정 (합성 사례로는 스케일을 맞춤)
- [ ] 법무 검토 완료 (5절 근거 조문별)
- [ ] 자동 확정 건의 설명문 (개인정보 보호법 제37조의2 대응) 템플릿 승인
- [ ] 사후 샘플 감사 담당자 지정, 샘플 비율 확정 (`with_post_audit_rate`)
- [ ] 확신도 기준 확정 (`with_min_confidence`, 기본 0.95)
- [ ] 승인자 사번과 법령 근거 조항을 운영 기록에 남김
- [ ] 모델 버전과 자가 검증 결과를 운영 로그에 남김 (`qmatmul_check` 출력 보관)

## 8. 실제 모델을 꽂아 본 결과

실제 zoro 백본과 `jev_head` 를 `Engine` 에 꽂고 자동화 모드를 켠 채 돌렸습니다 (`core/tests/real_models.rs` 의 `the_engine_with_the_real_model_never_finalizes_a_violation`, RX 6600).

| 사례 | 규칙 판정 | 모델이 규칙 판정에 준 확률 | 결과 |
| --- | --- | --- | --- |
| 모친이 임대인인 위장 임차 | 위반 | **91.7%** | 공무원 확인 (불리한 처분은 자동 확정 불가) |
| 서류 · 서명 · 계좌가 모두 맞는 청년월세 | 정상 | 기준별 최솟값 0.95 이상 | **자동 확정** |

- Gate 3 의 유리한 판정은 기준별로 따로 물어 가장 낮은 확률을 확신도로 씁니다 (9절의 방식 C).
- 불변식 1(불리한 처분은 자동 확정하지 않음)은 모델이 강하게 동의해도 지켜집니다.
- 모델 확신도는 프롬프트 형식과 스케일에 의존합니다. 형식을 바꾸면 값이 달라지므로 기준을 다시 맞춰야 합니다 ([jev-head.md](jev-head.md) 3 · 6절).
- 기준 0.95 는 GPU 경로에서 맞춘 값입니다. CPU 경로는 확률이 6.5% 포인트까지 다릅니다 ([zoro-backbone.md](zoro-backbone.md) 한계 8).

## 9. 작업을 나누면 자동화 비율이 오르는가

logis-center 의 분할 기법(Stanza · NMS · 어휘 뱅크 · SDS)을 살펴보고, 판단을 나눠 물으면 자동 확정이 늘어나는지 실제 모델로 쟀습니다 (`core/examples/automation_eval.rs`).

**logis-center 쪽 사실**: 게이트는 사건 단위로 계산됩니다. SDS 는 대부분 기록용이고, Stanza 는 검색 질의에만 돌며 작업 단위를 만들지 않고, NMS 는 짧은 질의의 단어 창에 돕니다. 전후 정확도나 자동화 수치는 저장소에 없습니다. 그래서 기법을 옮기는 대신 "한 판단을 나눠 묻기"로 바꿔 쟀습니다.

**실험**: 규칙이 유리하다고 본 42건(월세 · 보조금 · 영업신고 · 위임장)입니다. 깨끗한 건 23건은 실제로도 유리하고, 함정 19건은 관계망에는 없지만 사실 줄에 위반 신호가 있습니다 (규칙이 놓친 경우). 함정이 자동 확정되면 사고입니다.

**프롬프트 형식을 고치기 전**

| 방식 | 깨끗한 건 자동 확정 (기준 0.95) | 함정 통과 | 홀수 건만 | 질문 수 |
| --- | --- | --- | --- | --- |
| A 규칙 선택지 확률 (이전 방식) | 9/23 (39%) | 1/19 | 2/10, 사고 0/11 | 1 |
| B 유리한 처분끼리 합산 | 16/23 (70%) | **2/19** | 7/10, 사고 1/11 | 1 |
| **C 기준별로 따로 묻고 최솟값** | **11/23 (48%)** | **0/19** | 4/10, 사고 0/11 | 3~4 |
| D 유리 · 불리 두 선택지로 재질문 | 16/23 (70%) | 2/19 | 7/10, 사고 1/11 | 2 |

청년월세만 보면 A 3/12 (25%) → C 6/12 (50%) 이고 함정은 둘 다 0/8 입니다. **그래서 Gate 3 에 C 를 넣었습니다** (`verdict::judge_by_criteria`). 전체 질문에서 모델도 유리한 쪽을 골라야 하고, 기준마다 다시 물어 가장 낮은 확률이 확신도입니다. 기준 0.95 는 그대로이고 불변식도 그대로입니다. 호출은 판단당 1번에서 4번으로 늘어 ROCm 에서 약 2.7 s 입니다.

**B 를 쓰지 않은 이유**: 깨끗한 건은 가장 많이 늘지만 함정도 통과시킵니다. 고치기 전에는 "월세가 임차인 본인 계좌로 되돌아 입금됨"(0.966)과 "건축물 용도: 단독주택"(1.000)을, 고친 뒤에는 "건축물 용도: 단독주택"(0.978)을 통과시킵니다.

**프롬프트 형식을 고친 뒤** (선택지 위치 닫는따옴표, 스케일 1/32, [jev-head.md](jev-head.md) 6절)

| 방식 | 깨끗한 건 자동 확정 (기준 0.95) | 함정 통과 | 홀수 건만 | AUC |
| --- | --- | --- | --- | --- |
| A 규칙 선택지 확률 | 9/23 (39%) | 1/19 | 3/10, 사고 0/11 | 0.757 |
| B 유리한 처분끼리 합산 | 19/23 (83%) | 1/19 | 8/10, 사고 0/11 | 0.968 |
| **C 기준별로 따로 묻고 최솟값** | **18/23 (78%)** | **0/19** | **8/10, 사고 0/11** | **0.982** |
| D 유리 · 불리 두 선택지로 재질문 | 19/23 (83%) | 2/19 | 8/10, 사고 1/11 | 0.966 |

**방식 C 의 자동 확정이 11/23 에서 18/23 으로 늘었고 함정 통과는 그대로 0 입니다.** 깨끗한 보조금 5건을 모두 위반으로 잘못 보던 문제도 사라져서 5건 모두 자동 확정됩니다. 기준 0.95 는 그대로입니다.

형식과 기준을 고른 뒤 처음 돌린 20건에서는 깨끗한 건 6/9, 함정 0/11 입니다 (`automation_eval fresh`). **그래서 자동화 비율은 67 ~ 78% 로 봅니다.**

지금도 멈추는 깨끗한 건 5건은 이체 · 소득 사실이 붙은 월세 2건, 동명이인 1건, 위임장 2건입니다. 공무원에게 가므로 안전한 쪽으로 멈춘 것입니다.

**같은 사실을 명세 Part 6 의 JSON 구조로 물은 결과** (`automation_eval format`)

| 사례 | 결과 | 맞는가 |
| --- | --- | --- |
| 깨끗한 보조금 | 정상 0.993 | ✓ |
| 영수증 차액 18만 원, 관계 없음 | 보완 필요 0.737 | ✓ (기준 미만이라 공무원) |
| 분할 결제 | 위반 0.986 | ✓ |
| 특수관계 + 차액 | 위반 0.369 | ✓ (근소) |
| 월세 경로 없음 | 정상 0.918 | ✓ (기준 미만) |
| 특수관계만 있음 | 정상 0.813 | ✗ (기준 미만이라 멈춤) |
| 모친 동일세대 1홉 | 정상 0.927 | ✗ (기준 미만이라 멈춤) |

관계망 경로를 글로 넣은 구조에서는 모델이 관계를 잘 읽지 못합니다. 관계 판단이 규칙의 몫인 이유이고, 틀린 두 건도 기준 0.95 밑이라 자동 확정되지는 않습니다.

**이 수치의 한계**

- 사례는 모두 제가 쓴 합성 글이고 형식과 기준도 그 사례에서 골랐습니다. 비율은 방향만 보여 주며, 그림자 운영 없이 운영 수치로 쓰면 안 됩니다.
- **모델은 안전망이 아닙니다.** "건축물 용도: 단독주택"에 C 도 0.87 을 주고, "거래처 대표: 단체 총무의 배우자"에는 0.92 를 줍니다. 0.95 밑이라 멈췄을 뿐입니다. 기간 · 용도 · 관계 같은 판단은 규칙이 해야 합니다.

## 10. 모델이 쓰는 초안

명세의 `Trida` 생성 모드입니다 (`core/src/drafting.rs`). 판단과 같은 백본을 쓰고, 생성 경로는 [zoro-backbone.md](zoro-backbone.md) 의 "글쓰기" 절에 있습니다. **초안은 처분이 아닙니다.** 쓰는 모델이 위반 건을 적격이라고 써도 처분은 규칙이 정합니다 (`drafts_never_change_the_decision`).

| 초안 | 언제 | 어디로 가나 |
| --- | --- | --- |
| 고충민원 요약 (요지 · 요구 · 부서) | Gate 0 이 고충민원으로 분류했을 때 | 공무원 화면 (`ActiveSession.draft`). 자동화 모드에서도 공무원이 처리합니다 |
| 자유 서술 소명 정규화 | Gate 2 의 소명이 자유 서술일 때 | 표준 소명으로 바꿔 규칙에 넘깁니다. 영수증을 요구하거나 공무원에게 넘기는 길로만 갑니다 |
| 심사 의견 | 확정 문서를 만들 때 | 내부결재 문서에 "모델 작성, 공무원 확인 전" 표시와 함께 붙습니다 |

**모델의 글을 그대로 믿지 않습니다.**

- 글의 숫자 · 금액 · 날짜 · 시간을 모두 원문과 대조합니다 (`factcheck`). `20만 원` = `200,000원`, `일곱 시` = `7시`, `석 달` = `3개월` 처럼 표기가 달라도 값이 같으면 통과입니다.
- 요약의 숫자가 어긋나면 원문의 숫자를 알려 주고 한 번 다시 쓰게 합니다. 그래도 어긋나면 `verified = false` 와 걸린 내용을 공무원 화면에 띄웁니다.
- 심사 의견은 숫자가 어긋나거나 영문 코드가 나오면 문서에 넣지 않습니다.
- 소명에 증빙 얘기가 없으면 모델이 영수증이 있다고 답해도 믿지 않고 영수증을 요구합니다.
- 길이 제한이나 반복으로 멈춘 글은 마지막으로 완성된 문장까지만 씁니다.
- 긴 숫자(전화번호 · 주민번호 · 계좌)는 모델에 가기 전에 가립니다. 감사 로그에는 민원 내용을 남기지 않습니다.
- 부서는 정해진 목록 안에서만 받습니다. 목록 밖이면 비워 두고 표시합니다.

**실측** (`core/examples/write_eval.rs`, ROCm, 합성 민원)

| 항목 | 결과 |
| --- | --- |
| 고충민원 16건: 숫자 대조 통과 | 14/16. 걸린 2건 중 1건은 "석 달치"를 "8개월치"로 바꾼 실제 환각이고, 1건은 부서를 못 고른 경우입니다 |
| 부서 일치 (지시문을 고치며 본 10건) | 10/10 |
| 부서 일치 (고친 뒤 처음 돌린 6건) | 5/6 |
| 소명 정규화 | 8/8 (명세 Case 2-C 의 보일러 수리비 포함) |
| 시간 | 토큰당 30 ms, 요약 건당 2.5 ~ 2.9 s, 소명 건당 0.8 s |

처음에는 소명이 7/8, 부서가 8/10 이었습니다. 지시문에 부서가 하는 일을 넣고 증빙 낱말 검사를 넣어 고쳤습니다.

**한계**

- 숫자가 아닌 내용의 왜곡은 잡지 못합니다. 요약은 공무원이 원문과 함께 봐야 합니다.
- 합성 민원은 제가 쓴 짧은 글입니다. 실제 악필 OCR 결과로 재지 않았습니다.
- 명세의 250 ms 는 나오지 않습니다. 이 GPU 에서 토큰당 30 ms 이고 프롬프트를 읽는 데 약 1 s 가 듭니다 ([zoro-backbone.md](zoro-backbone.md) 자기 추측 디코딩).
